# API Reference

Interactive docs are auto-generated by FastAPI at `/docs` (Swagger) and `/redoc` once the
server is running (`uvicorn career_intel.api.main:app --reload`).

## Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Liveness check |
| POST | `/resume/upload` | Upload PDF/DOCX/TXT, extract text, and detect common resume sections (10 MiB default; configurable with `MAX_RESUME_BYTES`) |
| POST | `/skills/extract` | Extract canonical skills with category, source text span, offsets, and heuristic confidence metadata |
| POST | `/job/skills` | Extract canonical required skills and evidence from a job description |
| POST | `/classify/role` | Predict job-role label for a resume/JD (classical ML pipeline) |
| POST | `/resume/missing-skills` | Diff candidate vs. required skills |
| POST | `/recommend/rank-jobs` | Rank job descriptions by embedding similarity to a resume |
| POST | `/search/index-jobs` | Add/upsert job documents in the persistent Chroma index |
| POST | `/search/hybrid` | Retrieve jobs using dense vectors, BM25, and reciprocal-rank fusion |
| POST | `/search/recommend` | Use the configured LLM to explain top retrieved jobs with source-verified candidate/job quotes |
| POST | `/github/profile` | Analyze public GitHub repository metadata, manifests, and README skill evidence |
| POST | `/analyze/complete` | Fast resume/JD analysis, weighted gaps, and roadmap; does not call the LLM |
| POST | `/analyze/explanation` | Generate a source-grounded AI explanation of strengths and skill gaps (local LLM; may take longer) |
| POST | `/genai/rewrite-bullets` | Generate STAR-style rewrites using the configured LLM (may take longer locally) |
| POST | `/genai/interview-prep` | Generate interview practice using the configured LLM (may take longer locally) |

All responses include an `X-Response-Time-ms` header (used for the API latency evaluation metric).

Scanned PDFs use local Tesseract OCR when enabled. Install the Tesseract executable and English language data; configure `TESSERACT_CMD` if it is not on `PATH`. OCR is enabled by default, limited to 20 pages per resume, and can be configured with `RESUME_OCR_ENABLED`, `RESUME_OCR_LANGUAGE`, and `RESUME_OCR_MAX_PAGES`.

Skill extraction normalizes aliases using `config/skill_taxonomy.json`. Phrase matches return heuristic score `0.95`; NER-only spans return `0.65`. These are rule-based confidence tiers, **not calibrated probabilities**. A trained spaCy pipeline is loaded from `NER_MODEL_PATH` only when the path contains a valid spaCy model (`meta.json`); otherwise phrase matching remains active. NER-only skills absent from the ontology are returned with category `unmapped`.

Run `python scripts/index_job_descriptions.py` to persist the local vacancy CSV for hybrid search. BM25 is reconstructed from the stored job documents on API startup; relevance labels are needed before reporting ranking metrics.

`/search/recommend` is a separate, slower RAG action. It only returns a recommendation when the model's candidate and job quotes can be matched back to the supplied profile and retrieved posting. Its 0–2 evidence rubric covers closeness, relevance, accuracy, depth, ownership, verifiability, outcome, and transferability; these are model-assessed guidance scores, not calibrated hiring predictions.

The complete analysis response includes `ranked_skill_gaps`, evidence spans, `skill_match_score_method`, and `skill_match_score_explanation`. The score is a heuristic weighted coverage ratio; it is not a probability of hiring or role suitability.

Use `/analyze/explanation` after `/analyze/complete` for a longer AI-written profile narrative. The service verifies returned candidate and job quotes against the submitted text and omits claims without verifiable quotes. A skill not detected in the resume text is not proof that the candidate lacks that skill.
